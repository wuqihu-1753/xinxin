## 2｜两轴分类

- **主要数据架构**：[编目型](../../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) + [编年型](../../01-信息图形数据逻辑/01-编年型信息图形概念定义.md)。人物、生肖、祝福语和关系类型可按条目查找；年度出生量与节日活动依赖时间顺序。
- **主要表现类型**：**混合型信息图形**。统计柱形图、二维类别矩阵、定性关系网络、事件日程表、人物目录、主题插画不是同一统计图的多重装饰，而是具有独立问题与读数语法的模块。
- **次级表现类型**：时间轴/比较/列表；**不判为**“只有时间轴的编年型”，因为生肖关系和肖像名单不由时间轴统摄。

## A｜基本数据逻辑与字段架构

这不是一份单一关系表；至少存在下列实体数据和说明文本：
1. **出生统计**：`year, births_count, population_total, is_horse_year, geography, metric_source, unit`。年度出生数与人口应为不同系列；突出马年是标注/过滤操作，不是因果模型。
2. **生肖月历**：`zodiac_id, year_month, forecast_class, forecast_source, forecast_basis`，一张 12×12 分类矩阵。缺少预测方法时应标为“文化/民俗内容”，不可据此算相容概率。
3. **生肖关系**：`source_sign, target_sign, relation_class, relation_basis`，有中心星型连接但不一定有可比较的连续权重。
4. **生肖人物**：`person_id, name, birth_year, zodiac_sign, citation`；画面选登6人，无总体采样设计。
5. **节庆日程**：`event_id, start_date, end_date, event_label, calendar_basis`，包括日期节点和跨日条带。
6. **书法/俗语**：`phrase_id, characters, romanisation, translation, interpretation`，仅是文本说明。

**融合键**主要是主题“2026/马年”，其次是“生肖”“年份”“日/月”；它们不是同一可加总的统计指标。混合型不要求一张表包含所有字段，要求有清晰的模块关系与共同主题。

## B｜所借用的统计图形、数据变换与计算

| 子图 | 图形原型 | 可执行计算/判读 | 需严格避免的误读 |
|---|---|---|---|
| 年度出生统计 | 时间柱状图 + 马年节点强调 + 另列人口值 | 年度差值 `ΔB=B_t−B_(t−1)`；若源数据齐全可计算年变化率 `ΔB/B_(t−1)` | 不能仅因马年高亮认定生肖影响生育；出生数不是生育率 |
| 生肖月历 | 弧形“行×列”分类热力矩阵 | 分类匹配、月份查找，不预设连续数值公式 | 红色深浅 **不是** 经验证的幸运概率、效应大小或统计显著性 |
| 生肖关系 | 中心—外围关系图 | 定性关系类型查询；线条不是可直接加总流量 | 不能把线粗/长度解释为科学验证的人际相容度 |
| 节日活动 | 日期表 + 日历/Gantt式时段条 | 事件起止、跨日持续区间、同日共现 | 条带长度是日历跨度，不表示参与人数或重要性 |
| 人物/祝福目录 | 等距肖像图鉴、文字清单 | 分类查询、年份标注，无必要的统计计算 | 肖像尺度、排位不编码社会影响力 |

对图表中的年度柱，Y轴标有“Total births”，上方示例刻度可见约 50,000、100,000；不能将柱高与下方灰色总人口气泡面积当作同一单位。图中的预测数据来源/计算依据在截图中未给出可核实说明。

## C｜视觉编码（点、线、面、体、符号、色彩）

| 编码 | 可见表现（E1） | 信息功能与风险（E2） |
|---|---|---|
| **点** | 柱顶高亮标记、年份圆点、关系中心/生肖图标 | 精确年份标记与类别节点语义分开，禁止把图标尺寸当人数 |
| **线** | 红色柱形纵向刻线、半环月份分割、生肖关系虚实线、节庆时段条 | 同样是“线”，分别表示**时间范围、类别边界、定性关系、时间跨度**，需要局部图例 |
| **面** | 月历红色弧格、柱状图条形面积、灰色人口底圆、节日日历表格色带 | 柱形用长度比较；月历色块是分类；灰圆若只是注释底板，不可当同比例人口气泡 |
| **体** | 写实奔马立体明暗与肖像立体感 | 用来传递生动、速度、节庆情绪，**不承担数据大小编码** |
| **符号** | 12生肖红色剪影、肖像、汉字与拼音、QR码 | 文化识别/导航入口；不能默认属于Isotype的“一个图标代表N单位” |
| **色彩** | 高饱和红与粉红分级，主画面黑白灰底；灰色表现信息底板 | 同色在不同模块可能承担不同含义，应分模块独立解释三档预测色与关系连线 |
| **字体与层级** | 大型衬线标题 + 书法“马年” + 小字号英文数据标签 | 情绪/主题优先、图表精度为次级；长幅读图需要清楚模块标题和局部说明 |

## D｜数据／信息架构与版式

**组织方式是“主题总枢纽＋分散而有层次的多模块”**：
`出版时间/来源→生肖人物与月历→马年大标题+奔马视觉焦点→吉祥语/生肖关系→历年出生统计→节庆日历与来源`。

- 强烈的**竖版报纸编辑式网格**：顶部肖像跨栏，右上半环；中央大马跨越左右栏；底部横向铺满出生柱和节庆日历。并非所有模块逐项数值联动。
- **宏观—微观切换**：主题情绪 → 生肖群组 → 个人 → 香港人口历史 → 具体庆典日期。
- **同页包含多种时距**：生肖月份（二月起十二个月）、出生统计（年度长序列）、节庆活动（日）。三者必须分别读轴，不能按同一比例叠加。
- **信息来源可追溯程度不同**：人口与出生数列有政府统计资料提示；文化预测与生肖配对虽有图例，但在此截图中无法核实算法或严谨的经验依据。

## E｜视觉叙事架构

**主命题**：围绕2026马年把节庆文化与生活中可理解的时间、人物、统计信息汇成报道。
1. **吸引**：飞奔的马和戏剧性巨型标题建立情绪与主题；
2. **拓展**：名人马年、各生肖月历、关系配对提供轻量化“与自己相关”的入口；
3. **证据转换**：下方香港出生人数长序列用客观年度数据提供可比较事实，与上方民俗分类形成性质反差；
4. **行动/查阅**：节庆日历将读者导向具体日期；祝福文字提供文化使用情景；
5. **收束**：底部来源与QR码支持进一步查看，但不能替代对不同信息性质的解释。

这不是严格“单线故事”，更接近**可自由跳读的报纸专题多入口叙事**；通过主题一致性而非“每个指标都共用一个分母”实现混合。

## 3｜图形优势与局限

**优势（直接结构观察＋推断）**
- 数据柱形、环形分类矩阵、生肖关系图、日历Gantt条、肖像图鉴的**异质模块语法清楚**；
- 红色与灰阶使多个信息区有视觉统一性，巨幅手绘马图承担强烈主题识别；
- “故事感”不取代下方出生数的比较基线。

**风险／边界**
- 正式统计和文化预测在一版并置，若没有区分“经验预测”与“实测数量”，易造成可信度迁移。
- 生肖月历和生肖关系的色彩编码可能因都是红色而产生语义混淆，必须读局部图例。
- 紧密排版、肖像与小字标签在小屏幕阅读难度较高。
- 主题视觉造成注意偏好；**马年柱被高亮不能推断马年导致某种出生人数变化**。
- 数值抄录仅来源于用户所给版面，尚未独立核对原始香港政府时间序列。

## 4｜反向补充的可复用原则

1. **混合型可包含“统计＋文化知识＋定性关系＋可执行日历”，不强求全部模块都是图表**。
2. **“共同主题”不意味着“数据可相互计算”**：跨模块保留不同指标定义、来源、单位与时间粒度。
3. **同一色系可以统一版面，但必须局部建立语义图例**：半环的红色等级与配对关系的红线不是同一变量。
4. **用视觉焦点组织多入口阅读**，但避免它扭曲数字比较。
5. **区分科学统计与民俗预测的证据级别**，不得将预测分类当作已证实概率。

### 6.1 A／D｜建立不同语义的信息模块台账

| 模块ID（建议） | 图中主要模块 E1 | 数据粒度/类型 | 主要任务与证据边界 |
|---|---|---|---|
| H01 | 顶部六位人物肖像及出生年份 | 人物记录、年份属性 | 文化身份举例，不是生肖名人随机样本 |
| H02 | 右上生肖×月份预测半环矩阵 | 生肖×月×类别 | 读取Lucky/Neutral/Weaker分级，不作概率计算 |
| H03 | 主题标题、中文书法与奔马插画 | 文化主题锚点 | 主要用于识别马年，视觉面积不是统计量 |
| H04 | 左下吉祥祝福语 | 词条/拼音/译文 | 可独立查阅的文化名录 |
| H05 | 右下生肖关系示意 | 生肖对、关系类型 | 读定性线条图例，不能假设因果/相关系数 |
| H06 | 历年香港出生数柱形及特定年份人口标签 | 年份×人数，并有另一人口指标 | 唯一明确以连续量读数为核心的统计模块；指标与口径须分开 |
| H07 | 页脚2026年节庆逐日安排 | 日期/事件/跨度 | 时间事件和持续日期条，不是频数强弱 |

这些模块是**共同主题的互补知识岛**，不强制共享同一统计主键。可按下面的原子数据结构记录：

- **模块登记 modules**：module_id, topic_id, module_type, data_logic, visual_form, narrative_role, source_id。
- **年度出生表 annual_births**：year, births_count, geo_scope, source_id；**选定年份人口表**：year, population_count, population_reference_date, source_id。出生数和总人口不是同一个指标，若时点/口径不一致不能随意相除。
- **预测矩阵 fortune_cells**：zodiac_id, month_id, class_label, evidence_kind；“预测/民俗”必须保留来源性质，不得伪装为可验证的幸运概率。
- **关系边 compatibility_edges**：from_zodiac_id, to_zodiac_id, relation_type, legend_id；一个有向/无向属性依图例语义决定，不能从画面形状臆断。
- **人物/词项/节庆**：people(person_id, name, birth_year, source_id)；wishes(wish_id, text, pinyin, translation)；festival_events(event_id, event_name, start_date, end_date, source_id)。

一行一记录、一格一个原子值；跨模块仅以合适的共享年/主体或“主题性关联”连接，不做无根据的联合统计。以上为**重建设计蓝图**，不是已经获得外部可复算数据表。

### 6.2 B／C｜同一红色在不同子图中的意义

### 6.3 C｜Gestalt视线与模块组织（只在此02案例记录）

| 组织线索 | 画面依据 E1 | 可能的视觉作用 E2 |
|---|---|---|
| **图形—背景 Figure–Ground** | 中央深灰奔马与大面积白底；红色图形分布其周围 | 奔马作为视觉锚点；马的面积不代表出生数 |
| **共同区域 Common Region** | 预测矩阵、关系图、底部日历各有局部图例及分区 | 为不同子任务建立独立视觉单元，防止混读 |
| **相似 Similarity** | 半环内重复红粉格、人物肖像统一灰度风格 | 提示同一模块内部的项目属于统一模式 |
| **良好连续 Good Continuation** | 柱形公共基线、横向逐日节庆带 | 为年序与日期查找提供方向线索；不意味着跨图拥有同一连续量尺 |
| **邻近 Proximity** | 标注、图例靠近各自的矩阵/关系/柱图 | 可能帮助确认图例归属，仍需实测 |

### 6.4 D／E｜非线性专题中心的阅读体验

可从大奔马和总标题识别主题，再独立访问“H01人物/H02预测/H04祝福/H05关系/H06统计/H07节庆”等内容。页面上**主视觉的集中**与**阅读行为的非线性**可以同时成立。不同子图的单位与来源必须局部保留，不应为了版面统一把民俗与统计并成一种指标。

### 6.5 可执行的读者测试（尚未开展）

1. 要求读者分别找到“某生肖某月份的类别”“某个马年的出生人数”“某日节庆活动”，记录找错模块/图例的次数与耗时。
2. 出示预测半环和出生柱形，询问两种红色各自代表什么，排查“颜色相同即变量相同”的误解。
3. 询问中心奔马是否编码人口、生肖关系线是否代表被统计验证的相容概率，记录误读类型。
4. 在**不改变真实图例、原数据和文字**的前提下，试做各子模块围框/局部图例位置的版式对照；对照设计没有读者实测就不得宣称提高正确率。

**本例的可复用策略**：主题视觉中心＋异质并列信息岛＋模块级局部图例＋独立证据等级。适于文化专题/综合知识专题，但**不凭单一案例外推普遍受众效率**。

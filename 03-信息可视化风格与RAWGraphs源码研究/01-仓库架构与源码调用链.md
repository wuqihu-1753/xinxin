**读源码的先后**：入口 App.js → dataLoader hook → 数据解析 → ChartSelector → DataMapping → ChartPreviewWithOptions → ChartPreview → Exporter。分清 *App UI 状态* 和 *Core/Charts 内部图形算法*。

## B. 五阶段用户流程（逐项有代码）

1. **Load your data**：`DataLoader` 调用 `useDataLoader`，处理粘贴、上传、URL、SPARQL、样例/项目等，维护 `userInput/userData/data/dataTypes`。见 [useDataLoader](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/hooks/useDataLoader.js)。
2. **Choose a chart**：`ChartSelector` 从 `charts = baseCharts.concat(customCharts)` 中选图，按 metadata.categories 筛选；换图时重置 mapping、visualOptions 和 rawViz。见 [ChartSelector](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartSelector/ChartSelector.js)。
3. **Mapping**：`DataMapping` 使用 react-dnd，字段拖进 chart.dimensions；校验 required、多值字段、validTypes、aggregation。见 [ChartDimensionCard](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/DataMapping/ChartDimensionCard.js)。
4. **Customize**：`ChartOptions` 通过 core 的 `getOptionsConfig/getEnabledOptions` 生成控件，`ChartPreview` 把映射数据交给 `rawChart(...).renderToDOM(...)`。见 [ChartOptions](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartOptions/ChartOptions.js) 与 [ChartPreview](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartPreview/ChartPreview.js)。
5. **Export**：`Exporter` 序列化 SVG、或绘制到 canvas 并导出 PNG/JPG，也可保存 RAWGraphs 项目。见 [Exporter](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/Exporter/Exporter.js)。

数据流概要：

```text
用户 CSV/TSV/JSON/URL/SPARQL/样例
   ↓ useDataLoader + parser (+ Web Worker)
数据集 dataset + dataTypes
   ↓ ChartSelector：选择已注册图表
chart.metadata + chart.dimensions + chart.visualOptions
   ↓ DataMapping：字段→维度、有效性/聚合校验
mapping 对象
   ↓ ChartPreviewWithOptions：mapData（可在 Worker）
mappedData
   ↓ ChartPreview：rawChart + renderToDOM
rawViz（DOM 中的 SVG 等）
   ↓ Exporter：SVG | PNG | JPG | .rawgraphs
```

这是一份**工作流抽象图**，并非源码中自带的官方架构图。

## C. 状态变化与校验逻辑

- `App.js` 将 `currentChart, mapping, visualOptions, rawViz` 分开维护；改变 chart 后调用 getDefaultOptionsValues 重置选项。
- 数据列名变化时清除旧 mapping，避免将旧字段误对接新表。
- `ChartPreview.js` 实际检查：缺必填维度、multiple 维度数量不足、映射数据类型不符合 validTypes、mappedData 尚未就绪。这些校验使“画面正确”以前先保证映射格式基本正确。
- 这些前端约束**不等于**检查数据真实性、统计口径、异常值因果或视觉编码有效性；这些仍需人工或外部验证。

## D. 前后端/构建结构

- `package.json`：React 18.3.1；d3 ^7.2.0；Vite ^7.3.6；Sass；React Bootstrap 1.5（UI）。
- `vite.config.js`：支持在 `.js` 文件中转译 JSX；对部分 Node 风格依赖添加 process/global 兼容；输出目录 build。
- `src/worker/index.js`、`src/worker/worker.js`：Comlink 把 parseDataset、mapData 分给 Web Worker，减少主线程计算压力；并不能据此声称大数据量下所有图都具有某固定性能。
- `index.html`：包含 Google Analytics 标签，故“用户原始数据仅浏览器处理”和“页面完全不产生外部请求”**不是同义句**。
- `RAWGraphs-modernization-report.md` 是仓库内一份**2026-08-24 状态报告**，记载 CRA→Vite 迁移及 SPARQL/Node兼容问题；实际仓库该快照的 `vite.config.js` 和 `package.json` 已可证实 Vite 配置存在。仍不可把该报告中每一项性能数字当成独立复测结果。

## E. 对信息设计研究的价值（DESIGN）

**最重要的设计分层**：数据层（字段/类型/聚合）→图形机制层（尺寸、位置、颜色和路径）→视觉风格层（界面参数与可编辑 SVG）→完整信息图形叙事层（标题、证据、注释、案例）。RAWGraphs 在**图表机制层**和**矢量基础层**强，整版信息图形的编排与叙事仍需设计者完成。

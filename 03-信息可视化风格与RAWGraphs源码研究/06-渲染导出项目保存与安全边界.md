## A｜图表渲染链（SRC）

- ChartPreviewWithOptions 先把 mappedData 准备好（若 `WEBWORKER_ACTIVE=true`，通过 `mapDataInWorker`）；
- ChartPreview 校验 required、multiple、validTypes，随后使用 Core 的 `rawChart(...)` 构建实例并调用 `renderToDOM`；
- visualOptions 通过 debounce 减少连续刷新；
- 原生 DOM 中的可视节点被保存为 `rawViz`，供 Exporter 使用。

## B｜Exporter.js 中的实际格式

| 格式 | 代码操作 | 实用价值 | 局限 |
|---|---|---|---|
| **SVG** | `XMLSerializer` 序列化 `rawViz._node.firstChild`，以 `image/svg+xml` Blob 下载 | 矢量编辑、论文与印刷前期结构化图形 | 后续编辑若改变比例需核对；复杂字体/资源的兼容性应实测 |
| **PNG** | 将SVG作为Image绘制到 canvas，再调用 `canvas.toDataURL('image/png')` | 便于展示、PPT及位图平台 | 输出像素宽高由 SVG 节点的 `clientWidth/clientHeight` 决定；源码此处未实现单独的300dpi/8K控制 |
| **JPG** | 同上但 `toDataURL('image/jpeg')` | 普通展示/图片平台 | 有损格式，透明度和细线质量要另检查 |
| **.rawgraphs** | App 使用 `serializeProject` 组织项目状态；Exporter `JSON.stringify` 下载 | 可恢复图表、映射、视觉选项与部分数据状态 | 项目不是最终平面设计文件；跨版本兼容性需测试 |

源文件：[Exporter.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/Exporter/Exporter.js)、[App.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/App.js)。

**重要辨别**：SVG能在矢量编辑器打开，并不保证“每个元素都是 Illustrator 原生可编辑数据绑定对象”；SVG输出是已经渲染的图元，仍应保留原始表和项目文件用于复算。

## C｜项目序列化与恢复（SRC）

`App.exportProject` 传入：
`userInput, userData, userDataType, parseError, unstackedData, unstackedColumns, data, separator, thousandsSeparator, decimalsSeparator, locale, stackDimension, dataSource, currentChart, mapping, visualOptions, customChart`。

`App.importProject` 使用 Core 的 `deserializeProject`，重新设数据、当前图表、mapping、visualOptions；对于外部自定义图表可能要求用户确认执行其代码。源码还对导入的复杂 colorScale 选项附 `__loaded` 标记，以便避免误用新默认值。

**建议（DESIGN）**：每次正式案例保存“源CSV/JSON + .rawgraphs 项目 + SVG + 修饰后设计稿 + 资料来源与改动日志”，而不只保存最后一张PNG。

## D｜隐私：README 的表述与源码的边界

- README 声明数据在浏览器内处理、不做服务端数据处理或存储。这是仓库的**设计承诺**；本次代码读到的数据解析、映射和渲染主要发生在浏览器及其 Worker 中。
- 但 `UrlFetch.js` 和 `SparqlFetch.js` **明确发出浏览器网络请求**，而 `index.html` 明确加载 Google Analytics；因此不能写成“APP完全不与外网通信”。
- `useCustomCharts.js` 使用 `localStorage` 与浏览器 `Cache Storage` 持久化用户添加的自定义图表资源；这与 README 的“没有服务器存储原始用户表格”并不矛盾，但意味着**有浏览器本地持久化**。
- 是否存在其他遥测、是否向第三方发送具体导入数据、浏览器扩展/代理/远端服务安全等，不能仅凭这些源码得到绝对的“无泄露保证”。

## E｜外部自定义图表安全（必须说明）

`useSafeCustomCharts.js` 的 URL allowlist 目前只包括 `localhost`；NPM 包没有配置免确认白名单。URL/NPM/本地 JS 文件以及项目中引用的自定义图表，通常进入**用户确认**流程。

但 **确认弹窗不是沙盒执行**：`rawRequire.js` 中可见加载脚本标签、动态引入外部 JavaScript 的机制，用户确认只是告知风险，**不能把它当作恶意代码绝对隔离**。可行措施：
- 只加载可信且能检查来源的自定义图表代码；
- 不要把包含敏感数据的项目交给未知远端 JS；
- 为自定义扩展记录来源URL、版本、hash与授权信息；
- 在隔离浏览器/本地开发环境先测试扩展功能，再用于正式素材。

## F｜交付与版权

原始 app 仓库使用 **Apache-2.0**。本 03 文件夹只保留**自己撰写的分析文本、字段示例和链接**，不复制第三方完整源码、字体文件或样例图片。若后续真正分发其代码，应检查 Apache-2.0 署名和 NOTICE 等要求，且用户自制数据的权利与软件许可分别处理。

**结论**：RAWGraphs 是“表格→可编辑矢量图”的强工具；它不是数据发布真实性认证、统计审稿、印刷规范自动验收或网络安全沙盒。

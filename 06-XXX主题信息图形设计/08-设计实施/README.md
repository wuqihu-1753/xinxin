# 阶段08｜设计实施、产出与归档

**目的**：完成可编辑、可追溯、可发布的信息图形成品，并能从最终图形回到最初的来源和数据。

## 四个实施子目录

| 子目录 | 放什么 | 完成条件 |
|---|---|---|
| [01-草图与方案](01-草图与低保真/README.md) | 缩略草图、模块布局、备选方案、迭代理由 | 有主次、阅读路径、尺寸/构图 |
| [02-可编辑源文件](02-设计迭代/可编辑源文件/README.md) | SVG/AI/FIG/PSD/INDD/RAWGraphs工程等可编辑文件（按实际使用） | 图形数据、文字、分组可按需求修改 |
| [03-输出成品](03-最终交付/README.md) | 最终PNG/JPG/SVG/PDF等交付版本 | 尺寸、色彩模式、可读性与版权检查通过 |
| [04-复核与归档](03-最终交付/复核与归档/README.md) | 源数据与版本映射、导出设置、校验清单和最终审批记录 | 成品能够追溯到数据和设计决策 |

## 操作顺序
1. 从[阶段05叙事板](../05-叙事框架搭建/02-信息组织与版式结构/叙事结构与分镜模板.md)画多个版式草图；
2. 依据[阶段06视觉编码规范](../06-视觉编码/01-视觉编码矩阵/视觉编码与版式规范模板.md)对各模块建立统计图、插画、排版和图例；
3. 能用 RAWGraphs 的图表可保留 .rawgraphs + SVG；其他内容在实际的矢量/编辑软件继续深化；
4. 输出前对每一个具体统计图进行数值复查，确保图片/文本版权和可读性；
5. 建立交付文件名版本规则（例：`XXX_info_v01_print.pdf`；仅作命名示意），记录每次变化；
6. 将正式“信息轮盘”评价作为待补流程，不能因没有规则而编造测试合格结果。

## 交付定义
- 源数据与字段字典（不公开敏感数据）、必要的来源引用；
- 主要可编辑设计稿、独立图表SVG/源工程、链接素材；
- 面向媒介的最终成品与小尺寸预览；
- 图形数据准确性、版权、无障碍阅读和导出参数核查；
- 未完成或保留意见的风险说明。

当前目录只建立实施骨架，**未创建任何“已完成”设计图、源文件或虚构的最终图片**。

# 04｜字段 Mapping → 视觉编码 → 数据变换

> 核验文件：[src/components/DataMapping/DataMapping.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/DataMapping/DataMapping.js)、[src/components/DataMapping/ChartDimensionCard.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/DataMapping/ChartDimensionCard.js)、[src/components/ChartPreview/ChartPreview.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartPreview/ChartPreview.js)。精准的图表维度规范来自每个外部图表对象，不在 app 中逐图定义。

## A. 一项关键设计：数据字段不直接等于图形外观

RAWGraphs 将：
- `dataset`：用户解析完成的行记录；
- `dataTypes`：number、string、date 等类型；
- `currentChart.dimensions`：当前图表对输入语义的要求；
- `mapping`：具体字段分配；
- `visualOptions`：布局/颜色/尺寸的视觉参数；

分开管理。**同一原始数据可改变 chart、mapping、aggregation、visualOptions 得到不同图形**。

## B. 可从代码核验的 Mapping 对象结构

`DataMapping.js` 的映射值带有 `ids`、`value`、`config.aggregation`；`ChartDimensionCard.js` 还维护 `isValid` 与 `mappedType` 的有效性判断。

用于理解的**最小示例结构（非 RAWGraphs API 的官方完整 schema）**：

```json
{
  "color": {
    "ids": ["mapping-item-id"],
    "value": ["category"],
    "isValid": true,
    "mappedType": "string"
  }
}
```

注意：此 JSON 是按字段结构整理的**教学示意**，不能当作每个图表都具备 `color` 维度的保证。必须按实际所选图的 `dimensions` 动态判断。

## C. 交互约束与统计意义

| 代码字段/逻辑 | 已核实作用 | 信息设计的意义 |
|---|---|---|
| `required` | 必需维度未映射则提示缺失 | 避免缺少核心位置/大小字段仍输出 |
| `validTypes` | 数据类型与维度约束核验 | 不能把日期文字随意当数值长度 |
| `multiple` / `minValues` | 允许/要求多个输入字段时检查数量 | 并行坐标等多变量结构需要多个字段 |
| `aggregation` | 根据维度和字段类型从 Core 得出默认聚合，可在 UI 中修改 | 均值/总和/计数不同，改变图形表达对象 |
| `ids` 与 `value` | 维护拖入字段的身份和顺序 | 层级字段顺序或维度顺序可能影响图形结构 |
| `setMapping` | 拖拽/删改时更新状态 | 图形反馈依赖字段及模型稳定一致 |

拖拽功能见 `react-dnd` / `HTML5Backend` 导入。**拖拽交互不是统计图形计算本身**。

## D. mapping→render 的源码链

1. App 将 `dataset, dataTypes, mapping, visualOptions` 传给 ChartPreviewWithOptions；
2. `mapDataInWorker(chart.metadata.name, ...)` 可在 worker 里运行 `rawChart(...)._getVizData()`；
3. ChartPreview 确认必需映射、最小字段数、类型有效、数据已就绪；
4. `rawChart(chart, { data, mapping, dataTypes, visualOptions })` 获得 chart 实例；
5. `viz.renderToDOM(domRef.current,mappedData)` 绘图；
6. 视觉选项变化经过 200ms `useDebounce` 后触发更新。可参考 [ChartPreviewWithOptions](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartPreviewWIthOptions/ChartPreviewWithOptions.js) 和 [ChartPreview](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/components/ChartPreview/ChartPreview.js)。

## E. 对“点线面体符号色彩”的设计反向提取（DESIGN）

| 数据/图形输入 | 常见视觉通道 | 需核查的编码边界 |
|---|---|---|
| 时间 / 顺序 | 横向位置、日期格、时间区间条 | 实际时间不等间隔时保留刻度真实间距 |
| 名义类别 | 色相、形状、分面、小倍数 | 同类一致；类别色不可混当连续量 |
| 计数/数量 | 长度、位置、面积、带宽 | 必须写明单位、分母和比例尺度 |
| 两数值变量 | x/y位置（散点） | 轴范围、对数尺度、异常值解释 |
| 多维字段 | 并行轴、雷达轴、矩阵 | 轴量纲/归一化与比较任务必须匹配 |
| 层级 parent-child | 嵌套区域、树枝连接、环层级 | 包含关系/面积是否加总都要交代 |
| 网络 source-target | 弧线、矩阵、弦与流带 | 连接关系 ≠ 流量权重 ≠ 因果 |
| 地理 geometry | 位置、区域、坐标、路径 | Voronoi几何形态本身不等于真实地理地图 |

以上是面向信息设计的**编码研究建议**，并非 app 自动生成的逐图规范。

## F. 一项可测试的具体问题

同一份“城市名称、人口”数据，依次用条形图（排名）、treemap（总体结构，须有可加总口径）、circle packing（层级比较，需 parent 字段）展示：如果没有层级关系，**不能为了圆形审美随意伪造父节点**。工具给出图形选项，不负责保证你选的统计问题有意义。

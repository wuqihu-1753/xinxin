## B. parser.js 的真正解析顺序（SRC）

`PARSERS = [SparqlParser, JsonParser, CsvParser]`：依次尝试带 SparqlMarker 的查询结果、JSON 字符串、分隔文本（CSV/TSV/DSV）；只有对应解析成功才返回结果。

- **分隔符选择**：手动传入 separator 则按指定分隔符解析；未传时循环 separatorsList 候选，以解析出的列数等规则评分后选出。分隔候选来自 [constants.js](https://github.com/rawgraphs/rawgraphs-app/blob/48c3b2ee9ff412721a2c99c7bed38e734b3fa534/src/constants.js)。
- **JSON 规范化**：当选中 JSON 数组，`normalizeJsonArray` 能把标量包成 value 字段，把数组值中标量连接为文本，把对象中第一层标量字段摊平成类似 `object.key` 的列名；**不是递归无限层 JSON 规范化引擎**。
- **数据类型**：`useDataLoader` 调用 `@rawgraphs/rawgraphs-core.parseDataset`；前端 `DataGrid` 允许查看/修订 string、number、date 及日期格式。这里的 string/number/date 是 app 的字段解析类型，**不完全等于统计测量尺度中的名义、顺序、离散、连续四分类**。
- **数字格式与时间**：用户可配置小数分隔符、千分位分隔符、日期 locale 和分隔符；错误解析或丢失日期精度会改变视觉尺度。
- **Stack operation**：`useDataLoaderUtils/stack.js` 与 `handleStackOperation` 支持部分宽表/长表转换；完整转换约束需结合实际数据复测。
- **Worker**：`WEBWORKER_ACTIVE = true`，解析任务可由 Comlink 包装的 Worker 调用 `parseDataset`。

## C. 实验性字段字典（DESIGN，供 xinxin 案例数据记录）

| 字段 | 研究需要保存什么 | 重要原因 |
|---|---|---|
| field | 原始字段名及释义 | 确保映射可回溯 |
| parsed_type | string / number / date | 对应 app 解析逻辑 |
| semantic_type | 名义/有序/计数/连续/时间/地理键等 | 统计研究层，非 RAWGraphs 自带的完整分类 |
| unit | 人、美元、次、百分比、年等 | 防止异单位直接汇总 |
| missingness | 缺失值代码和比例 | 防止把空值误读为0 |
| source / timestamp | 数据出处和更新窗口 | 时间和数据口径可复核 |
| aggregation | sum/count/mean 等 | 同字段在不同聚合下图形语义不同 |
| reshape | 是否执行 stack/unstack | 防止结构变化后旧映射误配 |

## D. 可重现的解析检查顺序

1. 输入并标记来源、文件格式、源网址或授权状态。
2. 观察行列数、分隔符与第一行表头，确认 JSON/CSV 的结构。
3. 手工核查 number/date/string 识别是否符合字段实际含义。
4. 指定千分位、小数、日期 locale；不要把 `1,234` 混为小数 1.234。
5. 处理格式异常、缺失与“把对象摊平后丢失嵌套结构”问题。
6. 检查整理表中每行代表一个实体还是一次事件；是否需要宽长转换。
7. 才进入维度映射，记录所用统计聚合及筛选条件。

## E. 一个必须纠正的误区

“工具能直接导入 csv 并生成图形”**不等于**“数据已经清洗正确”。RAWGraphs 承担输入、类型推断、映射和渲染，但统计学意义上的分母一致、抽样误差、关联因果、数据伦理仍是设计者责任。这与 [xinxin 数据逻辑](../../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) 的规范一致。

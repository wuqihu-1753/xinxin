## 核心研究纪律

1. **01/02/03/04 是知识参考，05 是真实项目工作区**：不要把项目数据误存为02已核实CASE，也不要把设计风格等同数据逻辑。
2. **三条判断轴**：A 主要信息组织逻辑（编年/层级/编目/字母表/地理或其他）；B 02表现类型（文字列表、时间轴、照片、混合、词云等，允许多标签）；C 基础设计方法和视觉风格（ISOTYPE、扁平、摄影、手稿、编辑风等）。
3. **数据字段原子化**：**每列只有一个独立变量，每个单元格只保存一个该变量的值**；多坐标需拆列，不将“名字+GDP”写在一个单元格。图像通常储存一条资源路径/URL，具体素材与许可证分表登记。
4. **来源分级**：原始记录 / 公开文献直接陈述 / 推导公式或清洗 / 大模型建议 / 尚未核实推测须明确标注。模型不能充当虚构数据出处。
5. **数据先于视觉、但可设计驱动研究**：允许从构图灵感反向发现需要哪些字段，但不允许为了贴合形状编造数值。
6. **版本可回溯**：清洗前资料、字段变换、图形映射和后期排版分别保存，任何示例数字均不得冒充正式统计结论。
7. **版权与隐私**：引入图片、摄影作品和个人信息前确认来源、许可与必要的匿名化处理；不要在公开仓库提交敏感原始数据。

## 建议的信息流

```text
选题问题 → 资料检索与用户研究
         ↓
01 数据逻辑候选 + 02 类型标签 + 03 风格参考
         ↓
来源台账 → 原始资料 → 基础原子字段表
         ↓
字段组合与叙事模块（地点+坐标/名字+指标/事件+时间等）
         ↓
视觉编码规则 → 信息轮盘（指标待定）→ 草图/可编辑稿/交付
         ↖_________ 设计验证后回溯调整字段与问题 _________↙
```

**使用方式**：先填写各阶段 README 与模板，再建立真实数据文件。每份模板中的示例都标为“虚拟示例/仅演示结构”，不得作为 XXX 选题事实。

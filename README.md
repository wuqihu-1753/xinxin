## 新增案例图的工作流（必须遵循）

1. **保存原图**至 `02-信息图形类型案例/案例图/`，保留来源、作者、日期、版权/授权线索；未有权限时不上传受限原图，可仅记录链接或用户授权副本。
2. 在 `02-信息图形类型案例/案例库/` 建立 `CASE-0001-主题.md`，按模板记录观察事实、A–E 分析、信息架构、视觉编码、反例、把握度和图片相对路径。
3. 为案例标注**主要数据逻辑（01）**及**一个或多个表现类型（02）**，两层分类不得混为一谈。
4. 同步更新 `00-案例索引.md`、对应的 02 类型说明，以及关联的 01 概念定义。01 只使用**Markdown 文字链接**指向 02 的案例条目；**禁止将图片移入 01**。
5. 对照已有案例总结共性、差异及例外；只有案例证据支持的规则才写成“案例归纳”，并附具体链接。每次修订记录于 `CHANGELOG.md`。

**更新方式**：案例由用户后续在对话中提供时再分析、修改并提交仓库；GitHub 当前不会因为增加图片而自行触发 AI 分析或自动实时更新。若需要完全自动化，需额外搭建工作流。

## 写作规范

- 重要术语先给操作性定义，不把“混合型”“编年型”等不同分类维度当成一组互斥标签。
- **事实**（图中可见）与**推断**（设计意图、叙事效果）分开写；看不清或缺元数据的地方写“待核实”。
- 每条统计量明确单位、分母、范围及时间；象形图重复数量、面积或长度有定量含义时标出换算规则。
- Isotype风格图标并不自动表示符合某一 ISO 正式标准；不得作未经核实的标准认证表述。
- 使用相对链接连接文件，后续更新不得删掉原案例的证据编号及历史。

# 01｜编年型信息图形概念定义

> **文档状态：v1.1（2026-11-24）｜定义与A—E五维修订。** 此次吸收 [fengbaifan/Infographic-Style-Repository](https://github.com/fengbaifan/Infographic-Style-Repository/blob/main/01-信息图形数据逻辑/01-编年型信息图形概念定义.md) 的广义主序列定义及此前关于“链与容器”的讨论；保留本仓库原有的课件分析、CASE案例链接、F—I历史研究和证据等级说明。具体案例观察以02目录中的原记录为准，不能把概念示意当作已实测案例。

## 定义与识别边界

**编年型信息图形以具有确定先后约束的主序列组织信息，使读者能追踪阶段、步骤、事件或状态的推进关系。** 它的本质是一条有明确顺序意义的**链**，而不是直线时间轴、箭头、环形图等视觉容器。

对先后关系明确的单轨序列，可以抽象为：`S = (N₁, N₂, …, Nₙ)`，且具有 `N₁ ≺ N₂ ≺ … ≺ Nₙ` 的主导顺序。这里承诺的是**谁在前、谁在后**，不是每对节点之间的画面距离与真实时长成比例。

> **链是内容，轴是容器；保序不等于保距。** 数据逻辑决定需要保留的主顺序，视觉编码可以把顺序映射到直线、折返、蛇形、螺旋等多种路径，但应确保方向清楚、节点归属正确。

**分类口径**：吸收[Infographic-Style-Repository的广义主序列定义](https://github.com/fengbaifan/Infographic-Style-Repository/blob/main/01-信息图形数据逻辑/01-编年型信息图形概念定义.md)，编年型不仅可用于历史年代，也可用于**有明确前后依赖的非日期流程**。**时间是常见排序字段，而非每一条编年主链的必备列**。如果只是按字母、品类或大小排列、并未表达过程或发展，须优先检查字母表型、编目型或层级型。

### 1｜三项核心判据与数学边界

1. **单向性（主导阅读方向）**：读者能够沿主线区分起点、相继节点和终点/当前状态；不要求从左到右，也不意味着局部反馈一定不存在。
2. **低维度（主顺序维度）**：一个主要的 `order_key` 或前驱依赖主导信息组织。低维度不是表格只能有一两列；人物、图片、时间、数值等属性可以并存，只要不覆盖主序关系。
3. **不可逆性（顺序意义）**：随意交换关键节点会破坏事实先后或过程步骤的语义；不等于现实操作物理上绝不可能返回，也不等于读者不能回看前文。只有展示排序、没有真实过程依赖时，须标“有序展示”，不强称因果。

**典型单轨全序**：所有不同节点的先后都能判定，且关系可传递。**并行与偏序边界**：同日事件、同步任务、时间区间重叠、未知先后以及多主体并轨时，不得编造单一全序；可以设并行泳道、同级节点、未知时点或分支/反馈关系。单向指主线，不是整张图中不许有局部回返箭头。

**环形与循环边界**：只有主链存在明确起止时，闭合无入口的圆环会误导为“循环”；确实存在重复的生命周期、季节、财年或反馈过程则应标为周期/循环或主线＋反馈，不把回环误读成时间可逆。具有明确起点、终点和开口的环绕版式仍可以保留顺序。

### 2｜序位与度量分离：视觉编码为何能高度变化

| 维度 | 图形承诺 | 空间要求与可计算性 |
|---|---|---|
| **序位型／保序** | 只保证节点先后 | 节点可等距或非等距以适应排版；**不承诺**画面长度表示时长 |
| **度量型／保距** | 同时表达时间差或持续时间 | 必须有明确时间单位、比例及刻度；同一时间单位对应同一测量尺度 |
| **多属性复合型** | 主序之外另编码人口、金额、类别等 | 需独立数值轴/图例；新增属性不自动否定编年主逻辑 |

**示意（非作品数据）**：2010→2011间隔1年，2011→2014间隔3年。仅保序的事件条目可以把两段排成相同宽度，但不得用宽度推算年份；严格比例的时间路径上后一段应为前一段的3倍。

**保序映射**：只要沿路径读到的节点仍为N₁→N₂→…→Nₙ，视觉位置可以折弯、回转、展开为螺旋，页面的横坐标/纵坐标无需始终单调变化。路径曲率、跨行换列、半径或色块宽度**不自动**是时间度量。想表达“快慢与时间节奏”，必须有比例映射：直轴通常最便于建立均匀时间标尺，但弧形或折返路径若沿**路径长度**精确校准，也可以保留时距；不必把“只有直线能保距”当成数学定理。

### 3｜视觉变形前的四项识别边界

1. **主顺序是否必要**：移除/交换阶段后，核心意义是否受损？如果随便换顺序也成立，可能更接近编目清单；字母排序、规模排名另有各自数据逻辑。
2. **阅读路径是否明确**：起点、终点或当前阶段、推进方向是否可识别？无解释的分叉、折返、跨列跳跃与视觉自交会不会让人不知从哪里继续？
3. **是否保序而未假装保距**：图面采用等距事件列表还是比例量尺？如果没有明确定义，不得按节点间距、折返距离、螺旋半径或环形角度计算时长。
4. **循环与附加量纲是否区分**：非周期主链是否被画成无断点闭环？节点面积、色深、线宽若表达额外数据，是否有图例、单位和独立的阅读说明？

**路径自交的边界**：不加提示的自交默认应避免，因为交点可能制造先后歧义；如用桥接、断线、箭头或明确序号来区分跨越，自交不是绝对数学禁令。**视觉容器可以换，真实顺序和明确读法不能牺牲。**

## A｜基本的数据逻辑

编年型首先识别的是**主要顺序/过程依赖关系**，不是时间轴造型。一行记录一个节点，使用稳定的 `node_id`、`order_key`、`name`；需要表示前驱、平行轨道与反馈时另存 `predecessor_id`、`track_id`、`relation_kind` 或关系表。确实具有日期时再增加 `start_time`、`end_time`、`date_precision`；不应虚构日期以证明“是编年”。

- **全序单轨**：用于事实或步骤能够逐项判定先后的主链，按order_key排序；关系必须可传递。
- **并行偏序**：存在同时发生、区间重叠、分支与反馈时保留这些关系，禁止为视觉方便人为制造未经证实的唯一先后。
- **非时间序列**：任务步骤、工艺流程、状态迁移即使没有日期，只要具有决定性的前后依赖，也可归入本仓库广义编年型。
- **区别于因果图**：A在B之前，不自动证明A导致B。因果/前驱依赖须有独立定义或证据。

## B｜统计图形、统计方式与计算方式

**最小必要操作是验证顺序，不是计算指标。** 可处理有序节点、前驱条件、阶段/章节、路径关系；时长、事件频率、变化量和速率只在存在可靠原始量值时计算。

- **序位呈现**：事件序列、流程主链、交错竖轴、折返轴、蛇形/螺旋节点等，不具比例尺时仅供顺序查阅。
- **有可度量的时间**：阶段时长 `Δt=end−start`、相邻时距、按月年计数，以及折线的 `Δy=y₂−y₁` 和变化率，须同时有单位、时间粒度和口径；时点与区间不能混读。
- **借用图形**：事件时间轴、阶段链、甘特条、泳道、序列点图；只有数值明确时可借用折线/面积/柱形。视觉样式不是数据逻辑分类。
- **误读控制**：等距版式≠等时距；曲线≠数值趋势；箭头≠因果；累计量≠某段增量；选登节点数≠总体真实发生频率。

## C｜视觉编码与优化方法

| 视觉通道 | 可编码的内容 | 实践约束 |
|---|---|---|
| **点** | 阶段、事件、里程碑或转折节点 | 必须沿保序路径读取；节点大小不是默认的数值量 |
| **线** | 主线前进、前驱关系、局部回返 | 主线和反馈线分别标注；箭头与转折处方向明确 |
| **面** | 时间/阶段容器、章节区块、区间条 | 装饰分节可等宽；要表示持续时长必须声明比例 |
| **体** | 对象、场景或器物的立体形态 | 体积感用于识别，不能冒充未编码的统计数量 |
| **符号** | 动作、人物、主题或结果 | 图标与节点一一配对；重复图标不自动构成Isotype统计 |
| **色彩** | 阶段分类、泳道区别、关键转折 | 同义同色；连续值需图例，避免和顺序颜色混读 |
| **字体／文字** | 标题、序号、年份、关键描述、出处 | 先看路径再看细节，字号强调不等于数值重要度 |

### C1. 保序映射的视觉容器

| 容器形式 | 优点与用途 | 代价与补救 |
|---|---|---|
| **直线式** | 方向明确，易放置比例时间标尺 | 序列很长时可能拥挤 |
| **U形折返式** | 用二维宽度容纳长顺序 | 折返后读向改变；标起点、转弯和终点 |
| **蛇形／折叠式** | 适合宽画布、较多事件与行列 | 易读错跨行方向，需分段箭头/编号 |
| **螺旋式** | 用二维面积容纳密集章节节点 | 圈与圈之间的径向距离不自动按时间比例；注明内外读向 |
| **带开口的环绕式** | 利用环绕空间但保留首尾 | 清楚区分首尾，避免被误读为无限周期 |

**视觉优先级**：主顺序与读向 ＞ 节点归属 ＞ 阶段分组 ＞ 照片/图标/装饰。自交应优先避免；确有必要时用跨线桥接、断线或清晰序号消除歧义。**路径弯曲本身不是时间倒流。**

## D｜数据/信息架构

**一行一个节点、一列一个属性、一格一个原子值。** 不以Excel行列数量判断基本类型；数据层的先后顺序与版面层的几何位置要分开保存。

| order_key | node_id | name | predecessor_id | description |
|---:|---|---|---|---|
| 1 | N01 | 阶段甲 | — | 输入或起点 |
| 2 | N02 | 阶段乙 | N01 | 处理或演变 |
| 3 | N03 | 阶段丙 | N02 | 结果或终点 |

*以上为建模示意数据，不代表任何真实案例。*

| 建议表 | 独立字段 | 职责 |
|---|---|---|
| **nodes** | node_id, name, order_key, description, source_id | 节点记录及主顺序 |
| **relations** | from_node_id, to_node_id, relation_kind | 每行一条前驱、并行、反馈或分支关系 |
| **times（可选）** | node_id, start_time, end_time, time_precision, time_unit | 只有真实时长/日期才写入，不推测时距 |
| **layout** | node_id, path_order, path_segment, x_position, y_position, axis_mode | 记录画面路径，axis_mode区分ordinal或metric |
| **metrics（可选）** | node_id, measure_name, value, unit, source_id | 第二量纲的真实量值及来源 |

**架构步骤**：明确主序节点→辨别单轨/并行/反馈→定义真实顺序→选取视觉容器→进行保序映射→附加信息、来源与不确定性。**同一份有序数据可以配不同几何排版，主逻辑不因此改变。**

## E｜视觉叙事架构

**引入（问题或前提）→发展阶段→关键转折→当前/最终状态。** 主路径强调方向、节点次序与终点；支线可跳读，不得改变真实先后或假造因果。

- **单轨叙事**：起点和阶段顺序清楚，有明确终点或“仍在进行中”的标记；不是每个开放过程都必须虚构终结。
- **蛇形/螺旋叙事**：每个转折有显式续读提示。换容器只是在二维页面上放置一维主序，不是改变历史时间。
- **多轨/反馈叙事**：在共享可解释的参照下展示并行主体；反馈用独立关系线和图例说明，避免让局部回路吞没主序列。
- **叙事与证据边界**：标题提出解释角度，注释提供事实/来源，主链中的“前后”不自动证明“因为”。

## F｜课件核实与案例修订（2026-11-19）
> **课件来源说明**：以下页码指用户上传的《第三讲-信息图形类型学.pdf》，不是该页所展示原作的独立出版信息。原图未上传至公共仓库；局部案例分析只依据课件截图中可见的内容。

- **课件第2页**：将“编年型（Chronologically）”列为五种数据架构之一；第3页将其概括为单向、不可逆、顺序排列，单维为主，线性编码为主。这里将“不可逆”严格解读为**事件时间先后不能交换**，不意味着时间图形的阅读路径只能画成直线。
- **课件第3–5页**：可观察到曲线/圆环形的时间节点、时间标签、分布在几何轴两侧的事件注释；因此“线性”为顺序逻辑，不是必须采用水平直线。
- **课件第24页**：包豪斯人物与建筑沿年份排布，同时出现人物摄影、地图、图片说明，属于编年逻辑与时间轴视觉叙事结合。
- **课件第37页**：宇宙旅程作品使用流线与底部时间标尺，兼具对象编目和时间顺序；只能把“编年+编目”作为交叉标签，不应将曲线长度直接当作时间长度。
- **已分析案例**：[CASE-0001 编年回环时间轴](../02-信息图形类型案例/案例库/CASE-0001-编年回环时间轴.md)、[CASE-0011 包豪斯时间轴](../02-信息图形类型案例/案例库/CASE-0011-包豪斯时间轴.md)、[CASE-0024 宇宙旅程混合图](../02-信息图形类型案例/案例库/CASE-0024-宇宙旅程混合图.md)。
- **本次修订判定**：*支持* 时间键和先后顺序是核心；*修正* “单维”并非必要条件；*不能证实* 课件截图中的具体时间刻度是否完全按比例。

## G｜第二讲补充：时间数据类型与统计原型（v0.3）

- 《第二讲(2).pdf》p14–19把时间间隔列为可测量连续量，把“月份/年份”在具体案例中作为有序时间索引。**时间戳本身需要保留真实间距**，不应把每次事件之间的日期差当等宽类别。
- 本类型可以使用折线图比较数值随时间的变化，使用事件轴表示仅有发生顺序的记录；折线数值与时间轴节点不完全相同。
- 当日期不规则或缺测时，保持真实 X 轴间距或标出采用“等距事件序列”方法，避免视觉误导。
- **课件例证**：[CASE-0028 大型银行两期市值比较](../02-信息图形类型案例/案例库/CASE-0028-银行市值气泡图编码.md)（仅有两时点）；数据类型详见四分类与时间类型边界。


## H｜真实版面补充：混合型中的多时间尺度与生命周期（2026-11-23）

- [CASE-0032 马年生肖专题](../02-信息图形类型案例/案例库/CASE-0032-马年生肖专题混合信息图.md)里，**年度出生人数柱状图（约1960年以来）**、**2026年2月至次年1月的生肖预测分类矩阵**、**2026年2月16日至3月3日的节庆日历**并置。它们分别是年/月/日三级时间粒度，预测类别不等于年度人口指标；读图时必须辨认独立刻度、单位与信息来源。
- [CASE-0033 鸡与蛋生命周期](../02-信息图形类型案例/案例库/CASE-0033-鸡与蛋生命周期混合信息图.md)里，产蛋过程以**小时**、胚胎以**天**、成长以**周**编码，外圈的闭环是“生命重复”的**过程拓扑**，不是一条可等距读数的数值时间轴。

## I｜文字列表图中的编年主线与非比例时间导航（2026-11-23）

- [CASE-0035《Conspicuous Consumption》](../02-信息图形类型案例/案例库/CASE-0035-炫耀性消费世纪时间线信息图.md)从16世纪到21世纪按世纪标注多个消费主题，并以蓝色箭头和折线连接关键时代卡片。这是**编年型数据逻辑（年代不能任意互换）＋文字列表表现（每时期有可跳读关键词）**的明确交叉证据。
- **A 数据逻辑**：`era_id, century, stage_label, stage_order, item_ids, source`；时期顺序是一层键，世纪内的消费品条目是另一层键。
- **B 数值边界**：图中“16TH—21ST”是时间段名，不是以数字大小进行统计的观察值；蓝线的线长、弯折和每个时期的卡片高度均**没有被证明按真实时距成比例**。
- **C 视觉编码**：导览箭头承担有向阅读路径，不能当作时序数值曲线或因果链；世纪标题+重复的关键词框是导航信号。
- **D/E 架构叙事**：`概念命题→世纪推进→同期条目清单→现代转折→未来问题`；历史实例的选择是一种编辑性论证，时代相邻不等于被证实的因果关系。
- **与 [CASE-0034 披头士编目](../02-信息图形类型案例/案例库/CASE-0034-披头士四人组知识编目信息图.md) 对照**：两者都以文字列表为主表现形式，但后者没有可确认的强制时间主线。**01判定看时序是否必要，02判定看版面如何表达**。
